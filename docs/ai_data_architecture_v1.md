# AI Data Architecture v1

This document acts as the formal contract between Spring Boot and FastAPI, detailing ownership, database schemas, processing lifecycles, and model versioning.

---

## 1. Ownership

### Spring Boot Owns (Business Data)
Spring Boot is the **System of Record** for all transactional business domain entities.
```text
User
Resume File (Raw PDF bytes)
Jobs (Raw listings)
Applications
Bookmarks
Notifications
Authentication
Preferences
Companies
```

### FastAPI Owns (AI Data)
FastAPI is the **System of Record** for all AI understanding, analytics, embeddings, and machine learning outputs.
```text
Candidate Profiles
Job Profiles
Embeddings
Recommendations
Skill Gaps
Recommendation Reasons
Prompt Versions
Model Versions
AI Processing Status
```
* **Note:** FastAPI never owns raw resume PDFs or business logic. It stores structured JSON parses, vector mappings, and score heuristics.

## 3. Database Schema Layout

To optimize operations, Spring Boot and FastAPI share the same PostgreSQL server but are separated into distinct schemas:
* **`public` schema:** Managed by Spring Boot (DDL auto-updated by Hibernate).
* **`ai` schema:** Managed by FastAPI (contains AI models, profiles, embeddings, and status tables).

### Table: `ai.candidate_profiles`
Stores structured resume parsing results and their corresponding vector embeddings.
* `id` (UUID): Primary key.
* `resume_id` (BIGINT): Reference to Spring Boot resume ID. Unique index.
* `user_id` (BIGINT): Reference to Spring Boot user ID.
* `headline` (VARCHAR)
* `experience_years` (NUMERIC)
* `primary_role` (VARCHAR)
* `profile_json` (JSONB): Structured resume parts (skills, education, projects, experiences).
* `embedding` (VECTOR): 384-dimension vector (using `all-MiniLM-L6-v2`).
* `embedding_model` (VARCHAR)
* `llm_model` (VARCHAR)
* `prompt_version` (VARCHAR)
* `created_at` (TIMESTAMP)
* `updated_at` (TIMESTAMP)

### Table: `ai.job_profiles`
Stores normalized job profiles and their vector embeddings.
* `id` (UUID): Primary key.
* `job_id` (BIGINT): Reference to Spring Boot job ID. Unique index.
* `provider` (VARCHAR): External scraper or provider source (e.g., RemoteOK).
* `title` (VARCHAR)
* `company` (VARCHAR)
* `location` (VARCHAR)
* `experience` (VARCHAR)
* `profile_json` (JSONB): Standardized skills, benefits, requirements, and responsibilities.
* `embedding` (VECTOR): 384-dimension vector (using `all-MiniLM-L6-v2`).
* `embedding_model` (VARCHAR)
* `llm_model` (VARCHAR)
* `prompt_version` (VARCHAR)
* `created_at` (TIMESTAMP)
* `updated_at` (TIMESTAMP)

### Table: `ai.recommendation_results`
Stores matching calculations and generated natural language reasons.
* `id` (UUID): Primary key.
* `candidate_profile_id` (UUID): Foreign key referencing `ai.candidate_profiles`.
* `job_profile_id` (UUID): Foreign key referencing `ai.job_profiles`.
* `semantic_score` (NUMERIC): Cosine similarity score.
* `skill_score` (NUMERIC): Detailed skill coverage score.
* `experience_score` (NUMERIC): Role and experience matching score.
* `location_score` (NUMERIC): Location compatibility score.
* `education_score` (NUMERIC): Education credentials matching score.
* `final_score` (NUMERIC): Weighted aggregation of individual matches.
* `reason` (TEXT): Natural language explanation list generated by LLM.
* `created_at` (TIMESTAMP)

### Table: `ai.skill_gap`
Captures missing and matched technology skill details for a recommendation score.
* `id` (UUID): Primary key.
* `recommendation_id` (UUID): Foreign key referencing `ai.recommendation_results`.
* `matched_required` (TEXT[])
* `matched_preferred` (TEXT[])
* `missing_required` (TEXT[])
* `missing_preferred` (TEXT[])
* `coverage` (NUMERIC)

### Table: `ai.ai_models`
Configuration log containing model versions and prompt versions.
* `id` (UUID): Primary key.
* `provider` (VARCHAR)
* `llm_model` (VARCHAR)
* `embedding_model` (VARCHAR)
* `prompt_version` (VARCHAR)
* `created_at` (TIMESTAMP)

### Table: `ai.processing_status`
Manages asynchronous processing status for tracking failures or stale runs.
* `id` (UUID): Primary key.
* `entity_type` (VARCHAR): 'RESUME' or 'JOB'.
* `entity_id` (BIGINT): The database ID of the resume or job.
* `status` (VARCHAR): `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`, `STALE`.
* `started_at` (TIMESTAMP)
* `completed_at` (TIMESTAMP)
* `error_message` (TEXT)

## 4. Lifecycles

### Resume Upload Lifecycle
1. User uploads a PDF via the Frontend application.
2. Spring Boot saves raw PDF bytes and creates a `ResumeEntity` (references user, status set to `PROCESSING`).
3. Spring Boot calls FastAPI's `/api/v1/resume/process` asynchronously (multipart body).
4. FastAPI:
   * Extracts text, cleans text.
   * Parses text with LLM into `CandidateProfile` JSON.
   * Generates a 384-dimensional embedding vector.
   * Saves metadata into `ai.candidate_profiles` in FastAPI.
   * Returns `candidate_profile_id` to Spring Boot.
5. Spring Boot saves `candidate_profile_id` referencing the profile in PostgreSQL.
* **Result:** No raw JSON or embeddings are duplicated in Spring Boot. Spring Boot holds only the relational UUID reference.

### Job Sync Lifecycle
1. Spring Boot Job Scheduler pulls new jobs from RemoteOK / Arbeitnow APIs.
2. Spring Boot persists raw jobs to the PostgreSQL `jobs` table.
3. Spring Boot calls FastAPI's `/api/v1/job/process` endpoint.
4. FastAPI:
   * Parses raw job details into normalized `JobProfile` via LLM.
   * Generates 384-dimensional vector embedding.
   * Saves profile details and embedding vector in `ai.job_profiles`.
   * Returns `job_profile_id` to Spring Boot.
5. Spring Boot stores `job_profile_id` inside the `jobs` table.
* **Result:** Every job is embedded and LLM-parsed only once, at scrape-time.

### Recommendation Retrieval & Match Lifecycle
1. User requests recommendations.
2. Spring Boot forwards the user's `candidate_profile_id` to FastAPI's `/api/v1/recommendations/generate` endpoint.
3. FastAPI:
   * Loads Candidate Profile and its precalculated vector embedding.
   * Executes pgvector search in the database (`ai.job_profiles`) to find the **Top K (e.g. 100)** jobs using cosine distance.
   * Computes exact scores (Skill, Experience, Education, Location, and Final Weighted Score) for the top 100 jobs.
   * Generates natural language explanation reasons using LLM for the final top list.
   * Persists results to `ai.recommendation_results` and `ai.skill_gap`.
   * Returns a list of matched Job IDs (`job_id` references from Spring Boot).
4. Spring Boot loads the corresponding business `JobEntity` objects from PostgreSQL using the returned Job IDs and enriches the metadata.
5. Spring Boot returns enriched recommendation lists to the Frontend.

---

## 5. Model Versioning & States
* Every AI-generated embedding and profile includes: `llm_model`, `embedding_model`, and `prompt_version`.
* When prompts or models are updated, existing database entries are flagged as `STALE` in `ai.processing_status` and can be regenerated in background worker threads without disrupting the user.

---

## 6. AI Principles
1. **Analyze once, reuse many times.**
2. **LLMs explain, they don't make business decisions.**
3. **Scoring is deterministic.**
4. **Embeddings are generated once per version.**
5. **Spring Boot owns business data.**
6. **FastAPI owns AI knowledge.**
7. **Every AI artifact is versioned.**
8. **No duplicate ownership of data.**
